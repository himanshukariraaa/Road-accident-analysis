## 1. Introduction
Road accidents can cause injuries, loss of life and economic damage. This project demonstrates a data-science workflow for exploring accident-related attributes and classifying accident severity. It combines preprocessing, exploratory data analysis, supervised classification, evaluation and an interactive Streamlit interface.

## 2. Problem Statement
Historical accident records can be analyzed to identify patterns associated with recorded severity. A simple interactive tool can demonstrate how contextual features are passed through a trained classifier to estimate a severity class. Such a tool must be evaluated carefully and should not be treated as a reliable real-world safety system without validation.

## 3. Objectives
1. Load and validate a road-accident dataset.
2. Handle missing values and categorical features.
3. Explore patterns by severity, hour, weather and road type.
4. Train and compare Logistic Regression, Decision Tree and Random Forest classifiers.
5. Evaluate using accuracy, macro precision, macro recall, macro F1 and a confusion matrix.
6. Build an interactive prediction interface and dataset explorer.

## 5. Dataset Description and Integrity
The included demonstration CSV has 3,500 simulated records and nine columns: State, Year, Month, Hour, Weather_Condition, Road_Type, Vehicle_Type, Cause_of_Accident and Accident_Severity. The severity labels in this file were generated using a heuristic to create a runnable end-to-end demonstration. Therefore, the dataset is synthetic and cannot support claims about actual accident patterns or real-world predictive accuracy. For a research-grade version, replace it with a suitable public dataset, document its source and licence, and rerun the analysis.

## 6. Methodology
The workflow is: dataset loading → validation → missing-value imputation → one-hot encoding and numeric scaling → train/test split → model training → evaluation and comparison → model selection → interactive prediction.

The target variable is `Accident_Severity`, with classes Slight, Serious and Fatal. Input features include location/state, year, month, hour, weather, road type, vehicle type and reported cause. The data is split into 75% training and 25% test data using random seed 42; stratification is used where possible. Preprocessing is included in each scikit-learn pipeline so that imputation, encoding and scaling are fitted on the training portion only.

## 7. Models
**Logistic Regression:** a linear classification baseline that estimates class probabilities.  
**Decision Tree:** learns rule-like splits in the input features.  
**Random Forest:** combines predictions from multiple decision trees to reduce dependence on a single tree.

The application selects the model with the highest macro-F1 on the held-out test set. Actual metric values are generated by running the application and are intentionally not fabricated in this report.

## 8. Evaluation Metrics
- **Accuracy:** proportion of all test records classified correctly.
- **Precision:** among records predicted as a class, the proportion that truly belongs to that class.
- **Recall:** among actual records of a class, the proportion correctly identified.
- **F1-score:** harmonic mean of precision and recall.
- **Macro-F1:** average of the class-wise F1 scores with equal weight per class.
- **Confusion matrix:** compares actual labels with predicted labels.

## 9. Application Modules
1. **Overview & Analytics:** summary metrics and charts by severity, hour, weather and road type.
2. **Predict Severity:** accepts a hypothetical scenario and displays the predicted class and model class scores.
3. **Model Evaluation:** compares classifiers and displays a confusion matrix and classification report.
4. **Dataset Explorer:** filters records and exports filtered data as CSV.

## 10. Risk Interpretation
For demonstration, the application maps Slight to Low, Serious to Medium and Fatal to High. This is a project-defined interpretation of the predicted severity label, not a separately validated risk model. Model class scores are not guaranteed to be calibrated real-world probabilities.

## 11. Limitations
The supplied dataset is synthetic, features are limited, model scores are not externally validated, and the class mapping is simplified. A high metric on synthetic data does not imply generalization to actual accidents. The application is not intended for emergency, operational or real-time driving decisions.
